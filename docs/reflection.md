## 1. อะไรที่ AI ช่วยได้เร็วที่สุด

การร่างโครงหลายไฟล์ให้ครบตามที่โจทย์กำหนด (แยก `dc_bias.py` / `app.py` / template /
tests) และการเขียนเทสต์เริ่มต้นจากค่าที่คำนวณมือไว้แล้ว AI ช่วยให้เห็นภาพว่า
ข้อมูลไหลจากฟอร์ม → route → ฟังก์ชันคำนวณ → template อย่างไรภายในไม่กี่นาที
ซึ่งถ้าเขียนเองทั้งหมดน่าจะใช้เวลามากกว่าหลายเท่าในส่วน boilerplate ของ Flask

## 2. อะไรที่ต้องตรวจเอง และตรวจอย่างไร

- **สมการ**: คำนวณมือแยกอีกทางด้วยเครื่องคิดเลข แล้วเทียบทีละค่า (ดู `validation.md`)
  พบว่าต่างกันเฉพาะการปัดเศษทศนิยมตำแหน่งที่ 4
- **การแปลงหน่วย**: ตรวจว่า kΩ ถูกคูณ 1000 จริง โดยเทียบ `RTH` กับค่าที่คำนวณมือ
  (18.033 kΩ) ไม่ใช่ 18.033 Ω
- **การตัดสิน region**: ทดลอง VBE = 3 V และ RC = 10 kΩ เพื่อดูว่าเว็บเตือนจริง
  ไม่ใช่แสดง badge Active ตามค่า default
- **โค้ดที่ AI เขียน**: อ่าน `dc_bias.py` ทั้งไฟล์เพื่อยืนยันว่าไม่มี `import flask`
  และไม่มีตัวเลขผลลัพธ์ฝังอยู่ใน template

จุดที่ต้องแก้เอง: ช่วงแรก AI เขียนเทสต์กรณีฟิลด์หายแล้วผ่านทันที (ไม่เกิด RED)
เพราะ `parse_inputs()` รองรับ missing key อยู่แล้ว จึงต้องบันทึกไว้ว่าเทสต์ชุดนี้
ทำหน้าที่เป็น regression test ไม่ใช่เทสต์ที่พิสูจน์โค้ดใหม่

## 3. จุดที่แบบจำลองใช้ไม่ได้ และจะรู้ได้อย่างไร

แบบจำลอง forward-active ใช้ได้เฉพาะเมื่อ transistor อยู่ในย่านขยายสัญญาณจริง
ถ้า `VTH ≤ VBE` จะได้ IB ติดลบ (cutoff) และถ้า `VCE` ต่ำกว่า VCE(sat) ประมาณ 0.3 V
จะเข้าสู่ช่วงอิ่มตัว (saturation) — ในสองกรณีนี้สมการยังคำนวณได้ แต่คำตอบไม่มี
ความหมายทางกายภาพ

วิธีรู้: ให้โปรแกรม **ตรวจเงื่อนไขก่อนแสดงผล** และเตือนผู้ใช้ ไม่ปล่อยให้ตัวเลข
ติดลบแสดงเงียบ ๆ เพราะคนอ่านอาจเข้าใจว่าเป็นคำตอบที่ถูกต้อง และต้องยอมรับว่า
การหาคำตอบจริงในย่านนั้นต้องใช้แบบจำลองอิ่มตัวหรือ SPICE
